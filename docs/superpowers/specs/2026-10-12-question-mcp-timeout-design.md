# 提问 MCP 超时配置设计

## 状态

设计已获用户确认，等待规格文件评审后进入实施计划。

## 背景与目标

`ask_user_question` 当前由 `codeg-mcp` 通过本地 broker 注册问题，后端把问题广播给会话窗口，再等待用户提交答案。等待时长由 MCP 宿主自行决定；宿主超时后，工具请求可能被取消，问题卡也会随连接关闭而被清理。

本功能在“设置 → 常规”增加“提问 MCP 超时”配置，使用户可以控制 Codeg 侧的问题等待策略：

- 等待 10 分钟后再处理超时；
- 超时后额外重新提问 3 次；
- 重试耗尽后自动选择每个问题的第一个选项；
- 关闭自动选择后无限等待，直到用户回答或 Codeg 进程停止。

## 配置模型

沿用 `app_metadata` 持久化和现有的 `QuestionRuntimeConfig` 热更新机制，不新增数据表。

`QuestionSettings` 增加以下字段，所有数值在后端统一校验和限制：

| 字段 | 类型 | 默认值 | 范围 | 语义 |
| --- | --- | ---: | ---: | --- |
| `wait_timeout_minutes` | `u32` | 10 | 1–1440 | 单次提问等待时长，单位分钟 |
| `retry_count` | `u32` | 3 | 0–10 | 首次超时后的额外重新提问次数 |
| `auto_select_first_on_timeout` | `bool` | `true` | — | 重试耗尽后是否为每个问题选择第一个选项 |

已有的 `enabled` 字段保留，默认值不变。缺失或无法解析的新字段回退到上述默认值；保存时写入规范化后的值，避免非法配置进入运行时。

## 设置界面

在 `GeneralSettings` 现有常规设置列表中新增一个 `SettingsSection`，使用现有设置行和控件，不新增组件库依赖：

- 等待时长使用数字输入框，显示“分钟”，限制为 1–1440；
- 重新提问次数使用数字输入框，显示“次”，限制为 0–10；
- “超时后自动选择第一个选项”使用开关；
- 自动选择关闭时，在说明中明确表示会无限等待，等待时长和重提次数暂不生效；
- 三项配置统一保存，保存失败恢复上一次状态并显示现有风格的错误提示；
- 补齐项目支持的十种语言文案，中文文案作为本次新增界面的基准。

设置页面加载时调用现有提问设置读取接口，保存时调用现有提问设置写入接口。事件广播继续沿用 `QUESTION_SETTINGS_CHANGED_EVENT`，让其他窗口读取到同一份配置。

## 提问生命周期

### 自动选择开启

监听器收到一次 `BrokerAskRequest` 后，使用当前运行时配置执行以下循环：

1. 注册问题并广播问题卡，等待用户答案或连接关闭；
2. 等待达到 `wait_timeout_minutes` 后取消本轮问题卡；
3. 如果仍有剩余重提次数，重新注册同一组问题并广播新的问题卡；
4. 重试耗尽后，对每个问题选取 `options[0]`，生成 `QuestionOutcome` 返回给 MCP 工具；
5. 用户在任意一轮回答时立即返回用户答案，不再执行后续重提或自动选择。

如果问题在连接关闭或 Codeg 停止期间被清理，返回现有的 declined 结果，并确保问题卡、监听器和 broker 连接都被回收。

### 自动选择关闭

监听器不创建超时计时器，也不使用 `retry_count`，直接等待用户答案。只有用户回答、连接断开或 Codeg 进程停止可以结束等待。

MCP 宿主自身的请求超时属于客户端行为，Codeg 无法修改每个宿主内部的计时器。Codeg 侧会尽量保留问题状态；如果宿主仍保持 MCP 连接，用户回答可以完成原请求。如果宿主已经彻底关闭请求，则继续使用已有的纯文本兜底，确保问题不会无提示地丢失。

## 运行时数据流

```text
常规设置
  → get/set_question_settings
  → app_metadata
  → QuestionRuntimeConfig
  → DelegationListener
  → register / timeout / retry / first-option outcome
  → codeg-mcp
  → 智能体
```

`QuestionRuntimeConfig` 只保存经过校验的运行时快照。监听器每次收到提问时读取最新快照；一轮提问开始后使用该轮快照，避免用户在等待期间修改设置导致当前循环的计时和次数突然变化。

## 边界与错误处理

- `wait_timeout_minutes` 小于 1 或大于 1440 时夹到边界；`retry_count` 小于 0 或大于 10 时夹到边界。
- MCP `ask_user_question` 当前要求每个问题至少有两个选项，因此自动选择首项有确定结果；如果未来允许无选项问题，自动选择路径应返回 declined，而不能构造空选项答案。
- 同一会话只允许一个 pending question；重新提问必须先取消旧问题，再注册新问题，避免多个卡片同时存在。
- 用户回答和超时发生在同一时刻时，用户回答优先；超时分支只有在成功取得本轮等待权后才可以重新注册问题。
- 设置加载失败使用默认值并记录错误日志；设置保存失败不更新运行时配置。
- 每次进入重试或自动选择路径记录结构化日志，包含连接标识、当前轮次和最终动作，不记录问题内容或用户答案。

## 测试计划

### Rust

- 默认配置、缺失字段回退、非法值规范化；
- 设置保存后读取一致，运行时快照同步更新；
- 用户在首次等待内回答，直接返回用户答案；
- 单次超时后按配置重新注册问题；
- 重试次数耗尽后返回每个问题的第一个选项；
- 自动选择关闭时不触发超时和重试；
- 连接关闭和 Codeg 停止时清理 pending question；
- 用户回答与超时竞争时优先保留用户答案。

### 前端

- 常规设置正确加载三项配置并关联输入控件；
- 修改三项配置后发送完整规范化 payload；
- 保存失败恢复原值并显示错误；
- 自动选择关闭时显示无限等待说明；
- 保持已有 MCP 超时后的纯文本兜底回归测试。
